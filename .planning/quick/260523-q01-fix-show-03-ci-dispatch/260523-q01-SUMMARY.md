# Quick Task 260523-q01: Fix SHOW-03 CI Dispatch — Summary

**One-liner:** Fixed Run Smoke Test broken dispatch — added `workflow_dispatch:` trigger to ci.yml and replaced `res.json()` on 204 with GitHub runs API query to resolve run ID.

## Tasks Completed

### Task 1: Add `workflow_dispatch:` to ci.yml

Added `workflow_dispatch:` under the `on:` block in `.github/workflows/ci.yml`. Without this, the GitHub API returned 422 for any POST to the dispatch endpoint, preventing the Run Smoke Test button from triggering CI.

### Task 2: Fix /api/run-tests response parsing

- Removed `return_run_details: true` from dispatch body (not a GitHub API parameter)
- Removed `res.json()` call on the 204 No Content response (was throwing)
- After successful dispatch, waits 2 seconds then queries `/repos/{owner}/{repo}/actions/runs?event=workflow_dispatch&branch=main&per_page=5` to find the newly queued run
- Returns `{ runId: run.id, url: run.html_url }` or `{ runId: null, url: null }` if lookup fails

### Task 3 (discovered): Guard IDEShell against null runId

Updated `IDEShell.tsx` to handle `runId === null` (when the runs API returns empty after dispatch). Instead of polling `/api/run-status/null` (which returns 400), shows a warning log and stops gracefully.

## Files Modified

- `.github/workflows/ci.yml` — added `workflow_dispatch:` trigger
- `src/app/api/run-tests/route.ts` — fixed response handling, added runs API query
- `src/components/ide/IDEShell.tsx` — added `!runId` guard before polling loop
