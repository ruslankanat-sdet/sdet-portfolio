# Quick Task 260523-q01: Fix SHOW-03 CI Dispatch

## Context

The Run Smoke Test button in IDEShell is broken at two points (from milestone audit):

**Bug 1:** `.github/workflows/ci.yml` has no `workflow_dispatch:` trigger under `on:`. The GitHub API returns 422 when POSTing to the workflow dispatch endpoint without this trigger configured.

**Bug 2:** `/api/run-tests/route.ts` calls `res.json()` on the dispatch response. But GitHub's workflow dispatch endpoint returns **204 No Content** with no body — `res.json()` throws, `runId` becomes `undefined`, polling URL becomes `/api/run-status/undefined`, which the status route rejects with 400.

**End-to-end flow (how it should work):**
```
IDEShell button click
→ POST /api/run-tests
→ GitHub dispatch endpoint (POST .../dispatches) → 204 No Content
→ Wait briefly, then query GitHub /runs?event=workflow_dispatch&branch=main
→ Return { runId: run.id, url: run.html_url }
→ IDEShell polls /api/run-status/{runId} every ~3s
→ Terminal updates with job status
```

## Task 1: Add `workflow_dispatch:` to ci.yml

**File:** `.github/workflows/ci.yml`

Add `workflow_dispatch:` under the `on:` block (after `pull_request:`). No inputs needed — dispatching with `ref: main` is sufficient.

```yaml
on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main
  workflow_dispatch:
```

**Verify:** `grep "workflow_dispatch" .github/workflows/ci.yml` returns a match.

**Commit:** `fix(03-05): add workflow_dispatch trigger to ci.yml (SHOW-03)`

## Task 2: Fix /api/run-tests response parsing

**File:** `src/app/api/run-tests/route.ts`

**Remove:** `return_run_details: true` from the dispatch request body (not a valid GitHub API parameter).

**Fix:** After successful dispatch (204), query the GitHub runs API to find the newly queued run. Use a 2-second delay to let GitHub queue the run before querying.

```typescript
// After confirming res.ok (204):
// Wait briefly for GitHub to queue the run
await new Promise(r => setTimeout(r, 2000));

const runsRes = await fetch(
  `https://api.github.com/repos/${owner}/${repo}/actions/runs?event=workflow_dispatch&branch=main&per_page=5`,
  {
    headers: {
      Authorization: `Bearer ${token}`,
      Accept: 'application/vnd.github+json',
      'X-GitHub-Api-Version': '2022-11-28',
    },
  }
);

if (!runsRes.ok) {
  // Dispatch succeeded but we can't get the runId — return a partial success
  return Response.json({ runId: null, url: null });
}

const runsData = await runsRes.json();
const latestRun = runsData.workflow_runs?.[0];
return Response.json({
  runId: latestRun?.id ?? null,
  url: latestRun?.html_url ?? null,
});
```

**Note:** If `runId` is null (runs API returned empty), IDEShell will log "Run dispatched" but polling won't start. The terminal at least won't show "undefined" errors. The IDEShell already handles `!runId` case.

**Verify:** TypeScript type checks pass (`pnpm typecheck`).

**Commit:** `fix(03-05): fix run-tests route — query runs API after dispatch instead of parsing 204`
