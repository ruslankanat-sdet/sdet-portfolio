## Interaction Contract

### MOB-01: Mobile Sidebar Overlay

**Trigger:** `window.innerWidth <= 768` (SSR-safe check via `typeof window !== 'undefined'` guard, same pattern as existing IDEShell line 88).

**Backdrop:**
- Element: `<div>` rendered inside `.ideBody`, between `<Sidebar>` and `<div className={styles.main}>`
- Visibility: only when `sidebarOpen === true && isMobile === true`
- CSS: `position: fixed; inset: 0; z-index: 49; background: rgba(0, 0, 0, 0.5);`
- Use `position: fixed` (not `absolute`) so the backdrop covers the entire viewport including SiteHeader area if needed; alternatively `position: absolute` scoped to `.ideBody` with `position: relative` already present on that element at `@media (max-width: 768px)` — use absolute for parity with existing SHELL-05 scaffolding.
- Animation: `opacity` transition 0.2s ease to match sidebar slide transition.
- Click/tap: calls `toggleSidebar()` to close sidebar.
- Pointer events: only active when rendered (conditional render, not CSS visibility).

**Auto-close on file tap (D-01):**
- New optional prop on `Sidebar`: `onSelect?: () => void`
- `fileRow` onClick and onKeyDown: after `setActiveFile(name); openTab(name);` → call `onSelect?.()`.
- IDEShell passes `onSelect={toggleSidebar}` only when in mobile overlay mode. Guard: pass `undefined` on desktop so desktop file clicks do not close the explorer panel.
- Detection: IDEShell maintains an `isMobile` boolean state (same `window.innerWidth <= 768` check, initialized in same pattern as `sidebarOpen`).

**Keyboard accessibility:**
- When sidebar opens on mobile (focus management): move focus to the first interactive element inside the sidebar — either the first activity bar button or the first file row.
- When sidebar closes via backdrop click or file tap: return focus to the hamburger menu button.
- Backdrop element: `aria-hidden="true"` (it is decorative/dismissal; the sidebar itself is the interactive region).
- Sidebar `<aside>`: already has `aria-hidden={!sidebarOpen}`. Confirm this correctly removes it from the accessibility tree when closed.
- Trap focus inside sidebar when open on mobile: not required for v1.1 (sidebar already has visible focus styles; full trap is a v2 enhancement). Ensure Tab key can reach the close area (backdrop or hamburger).

**Touch targets (WCAG AA):**
- All tappable elements must have a minimum touch target of 44×44px.
- File rows (`.treeRow`, `.treeFolder`): currently `padding: 4px 6px` + 12px line-height ≈ ~20px visible height. Add `min-height: 44px` inside `@media (max-width: 768px)` to meet WCAG AA. Use `align-items: center` (already set) to keep icon/label centered within the taller hit area.
- Activity bar buttons (`.actBtn`): currently 36×36px with an `::after { inset: -8px }` pseudo-element extending the hit area to ~52×52px — already compliant.
- Hamburger button (`.menuBtn`): currently 34×34px icon button. Add `@media (max-width: 768px) { .menuBtn { width: 44px; height: 44px; } }` to TopBar.module.css.
- Theme toggle button (`.iconBtn`): same 34×34px. Add the same 44px override in mobile media query.
- Run Smoke Test button (`.runBtn`): currently `padding: 9px 14px` ≈ ~38px height. Add `min-height: 44px` in mobile query.

### MOB-02: Code Overflow

**Status from codebase inspection:** `FileView.module.css` `.code` already has `overflow: auto; white-space: pre`. The `editorInner` has `overflow: hidden`. The code `<pre>` element with `overflow: auto` should already allow horizontal scrolling within the code area.

**Contract:** Confirm `.editorInner` does not clip the code's own scrollbar. If needed, change `.editorInner` from `overflow: hidden` to `overflow: visible` (or remove `overflow` entirely) at `@media (max-width: 768px)`. The `<pre>` element's `overflow: auto` (D-07) handles the actual scroll. No `overflow-x` change to `.code` is needed if `overflow: auto` is already set — verify at 375px in dev; if scrollbar appears and is functional, D-07 is already satisfied.

**Minimap:** Hide `.minimap` below 768px to reclaim horizontal space. Add `@media (max-width: 768px) { .minimap { display: none; } }` to `FileView.module.css`. This eliminates 70px of decorative width on narrow viewports.

### MOB-03: Terminal Text Wrapping

**Log text (D-06):**
- Target elements: `.log` and all its variant classes (`.logInfo`, `.logWarn`, `.logOk`, `.logFail`, `.logPass`).
- Add to `Terminal.module.css` inside `@media (max-width: 768px)`:
  ```css
  .log {
    white-space: pre-wrap;
    word-break: break-word;
  }
  ```
- The `[PASS]` / `[FAIL]` tag spans (`.logTag`) must not be affected. Because the tag spans are `inline` inside the `.log` block, `white-space: pre-wrap` on the parent allows wrapping between tokens but the tag itself stays visually intact. Verify in dev that the colored `[PASS]` / `[FAIL]` prefix does not break mid-tag.

**Terminal height (D-04):**
- Initialize `termHeight` to `120` when `window.innerWidth <= 768`. Same SSR guard as `sidebarOpen`.
- Change in IDEShell `useState<number>`: `useState<number>(() => { if (typeof window === 'undefined') return 220; return window.innerWidth <= 768 ? 120 : 220; })`.
- CSS safety net: add `@media (max-width: 768px) { .terminal { max-height: 180px; } }` in `Terminal.module.css` to prevent resize-to-huge by inertia if a future touch-drag is added.

**Resize handle (D-05):**
- Add to `Terminal.module.css`: `@media (max-width: 768px) { .termResizer { display: none; } }`.

### MOB-04: Header Nav (SiteHeader)

**Existing behavior:** `@media (max-width: 480px)` already hides `.separator` and `.title`, leaving only "Ruslan Kanatbek" and the nav link.

**481px–768px range (Claude's Discretion):** The full title "Senior SDET / QA Automation Engineer" renders. If it overflows the 44px header height or causes `.navLink` to be pushed off screen:
- Add `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` to `.title` inside `@media (max-width: 768px)`.
- Do not wrap the header to two lines — the header is 44px fixed height.
- The `.navLink` (About) must always be reachable; use `flex-shrink: 0` on the nav element to prevent it from being crushed.
- If needed, add `flex: 1; min-width: 0` to `.identity` so the title block shrinks before the nav link disappears.

**Touch target for nav link:** `.navLink` is currently inline text. At `@media (max-width: 768px)`, ensure `display: inline-flex; align-items: center; min-height: 44px; padding: 0 8px;` so it meets the 44px touch target requirement.

### MOB-05: About Page

**Table overflow (Claude's Discretion):** MDX may render `<table>` elements (skills, experience comparisons). Add to `about.module.css`:
```css
@media (max-width: 768px) {
  .pageWrapper table {
    display: block;
    overflow-x: auto;
    -webkit-overflow-scrolling: touch;
  }
}
```
This wraps any table inside the prose container with horizontal scroll rather than page-width overflow.

**Page wrapper padding:** The `.pageWrapper` has `padding: 48px 24px 80px`. On mobile (375px), 24px side padding is appropriate — no change needed. If any content still touches the viewport edge, reduce to `padding-left: 16px; padding-right: 16px` at 480px.

**`proseH1` size:** Currently 32px. On 375px screen this is acceptable — do not reduce; it is a name heading and size is intentional. Verify it does not overflow.

### UX-01: Pane Labels

**New CSS class (D-11):**
```css
.paneSubtitle {
  font-size: 11px;
  font-weight: 400;
  color: var(--text-faint);
  letter-spacing: 0.02em;
  font-family: var(--ui);
  margin-left: 6px;  /* gap after the primary header label */
}
```
Add to each relevant module CSS file, or create a shared utility class if the project's CSS Modules setup allows. Preferred: add directly to each module file to keep colocation.

**Separator character (D-10):**
- Use the `·` (middle dot, U+00B7) character inline in JSX.
- Wrap in `<span aria-hidden="true">` to prevent screen readers from reading "middle dot" or "bullet".
- Pattern: `<span aria-hidden="true"> · </span><span className={styles.paneSubtitle}>File browser</span>`

**Label placements (D-10):**

| Pane | Location in DOM | Existing element | Label to add |
|------|----------------|------------------|--------------|
| EXPLORER sidebar | `Sidebar.tsx` `.explorerHeader` | `<span>EXPLORER</span>` | `<span aria-hidden="true"> · </span><span className={styles.paneSubtitle}>File browser</span>` after the EXPLORER span, before the `explorerMeta` repo name |
| Editor | `EditorArea.tsx` breadcrumb bar (`.breadcrumb`) | `<span className={styles.crumbActive}>` last crumb | Append `<span aria-hidden="true"> · </span><span className={styles.paneSubtitle}>Code viewer</span>` after the active breadcrumb — or add to the breadcrumb `<div>` trailing right side using `margin-left: auto` |
| Terminal | `Terminal.tsx` `.termTabs` | `<div className={styles.termMeta}>playwright</div>` | Change the TERMINAL tab or add inline after "TERMINAL" text: when `tab === 'TERMINAL'` render `<span aria-hidden="true"> · </span><span className={styles.paneSubtitle}>Test output</span>` inside the active TERMINAL tab div |

**Always visible (D-09):** Labels are statically rendered, not hover-triggered, not toggled. The subtitle spans are always present in the DOM.

**Label text exact values (D-10):**
- Explorer: `EXPLORER · File browser`
- Editor: `· Code viewer` (the `·` follows the active breadcrumb filename)
- Terminal: `TERMINAL · Test output` (inline within the TERMINAL tab when it is the active tab — `tab === 'TERMINAL'`)

## TopBar at ≤375px (Claude's Discretion)

At `max-width: 480px`, the TopBar has the hamburger (visible since SHELL-05 at ≤768px) and the right section (theme toggle, Run Smoke Test button). Elements already hidden at 920px: `logoText`, `branch`, `clock`. All status badges hidden at 1060px.

**Remaining elements at 480px:** hamburger + logoMark icon (34px square) + tabDivider + Run Smoke Test button + theme toggle icon.

**Contract:** Add `@media (max-width: 480px)` to `TopBar.module.css`:
- Hide `.tabDivider`: `display: none` — purely decorative separator.
- Hide `.logoMark`: `display: none` at ≤480px if the Run Smoke Test button is being crowded. Evaluate visually first; if 375px width still fits logo mark + hamburger + run button + theme toggle without overlap, keep logo mark.
- Hide `.runShortcut` badge (`⌘↵`) inside the run button: `display: none` — saves ~40px of run button width.
- Minimum run button: keep `<Play icon>` + label text "Run Smoke Test" (or "Run" if truncation is needed — evaluate at 375px; prefer full label if it fits with `min-height: 44px`).

**Always visible at ≤375px:**
- Hamburger menu button (opens sidebar)
- Run Smoke Test button (primary action of the portfolio)
- Theme toggle button
