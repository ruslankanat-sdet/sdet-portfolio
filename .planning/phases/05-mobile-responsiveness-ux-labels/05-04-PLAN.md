<objective>
Close two UAT gaps from Phase 05 testing.

Gap 1 (major, test 4): Terminal not visible on desktop; height inconsistent across file tabs on mobile. Root cause: .site-main in globals.css is not a flex container (missing display:flex; flex-direction:column), so .ideBody's flex:1 has no effect. .ideBody grows to intrinsic content height based on how many lines the active file has. Different files → different EditorArea heights → different .ideBody heights. With overflow:hidden on .site-main the terminal at the bottom is clipped to varying degrees. On desktop the file content is long enough to clip it entirely. On mobile shorter files expose the terminal partially, longer files clip more — appearing as height changing per file tab.

Gap 2 (cosmetic, test 8): The EditorArea breadcrumb right-label (separator + "Code viewer") renders misaligned. Root cause: .crumbSubtitleSep uses margin-left:auto to push itself right, but the following .paneSubtitle element is a separate sibling, causing a gap between separator and subtitle when the breadcrumb flexbox distributes space.

Purpose: Constrain .ideBody to the actual viewport height so the terminal is always fully visible and consistently sized regardless of file content. Also tighten breadcrumb label alignment.
Output: Updated globals.css (2 lines added to .site-main) and EditorArea.module.css (add .crumbRight grouping class).
</objective>

  <action>
    In src/app/globals.css, find the .site-main rule (currently lines 159–163). Add display:flex and flex-direction:column to it so that its flex children (.ideBody on the home page, .scrollContainer on the about page) can use flex:1 and height:100% respectively.

    The updated .site-main rule must be:

    .site-main {
      display: flex;
      flex-direction: column;
      flex: 1;
      min-height: 0;
      overflow: hidden;
    }

    Do not change any other rule. The .site-body rule above it already has display:flex; flex-direction:column — .site-main is a child of .site-body and will now propagate a flex context downward to .ideBody.

    Why this fixes the bug: .ideBody has flex:1 in IDEShell.module.css. Without a flex parent, flex:1 is ignored and .ideBody grows to intrinsic content height. IDEShell renders TopBar + .ideBody + StatusBar. Without flex:1, .ideBody is as tall as all its children (Sidebar + EditorArea + Terminal) — potentially taller than the viewport. With overflow:hidden on .site-main, the terminal at the bottom gets clipped. Adding display:flex; flex-direction:column to .site-main activates .ideBody's flex:1, constraining it to exactly the available height, keeping the terminal within view.

    The about page is not affected: .scrollContainer uses height:100%, which on a flex child equals the flex parent's allocated height — correct behavior.

    Update the inline comment on overflow:hidden to: "IDE landing: scroll managed inside IDEShell; /about scrolls via .scrollContainer child"
  </action>
