<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM <-> React state | Click handler on backdrop mutates `sidebarOpen` via `toggleSidebar`. This is idempotent UI state — no privileged action, no network call. |
| Server (SSR) <-> Client (hydration) | `isMobile` and `termHeight` initializers use `typeof window === 'undefined'` guard. SSR returns safe defaults (false / 220); client computes real values at mount. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-08 | Tampering | Backdrop click handler | accept | `toggleSidebar` is a no-arg toggle on local UI state. No network call, no data mutation, no auth implication. Worst case: a malicious script in the same origin could trigger sidebar open/close — already trivially possible without the backdrop. |
| T-05-09 | Information Disclosure | SSR/CSR mismatch | mitigate | SSR fallbacks (`return false` for isMobile, `return 220` for termHeight) match desktop defaults. The first client render will use real `window.innerWidth` — on a mobile device, this triggers a one-frame re-render with smaller `termHeight` and a possibly-rendered backdrop. React handles hydration mismatch warnings; no data leakage. Verified pattern (same as existing `sidebarOpen` initializer at line 87). |
| T-05-10 | Denial of Service | Resize listener absence | accept | We do NOT add a resize listener for isMobile (per CONTEXT.md decision: "snapshot taken at mount time"). A user who resizes a browser window after mount will not see the mobile/desktop split flip. This is intentional — adding a resize listener for v1.1 is out of scope. No DoS surface. |
| T-05-11 | Tampering | Backdrop z-index manipulation | accept | An attacker who can inject CSS into the page could override z-index — but they can also override any other CSS. CSS is not a security boundary. |
| T-05-12 | Spoofing | `aria-hidden="true"` on backdrop | accept | The backdrop is decorative (the sidebar is the interactive region). Screen-reader users dismiss via the hamburger button's "Close sidebar" aria-label. No identity / auth implications. |
| T-05-13 | Tampering | Build pipeline | accept | No new dependencies. No package installs in this plan. ASVS L1 supply-chain requirements not triggered. |

This plan introduces no new backend routes, no new auth/session changes, no new data persistence, no new external API calls, and no new dependencies. The only behavioral additions are mount-time `window.innerWidth` reads (SSR-guarded) and a conditional JSX render that mutates local UI state. No new attack surface beyond the existing v1.0 IDE state machine.
</threat_model>
