  <action>
    Iterative triage. The exact subset of files modified depends on what axe surfaces and what the existing styles already cover. Algorithm:

    Step 1: Collect violations. Run pnpm exec playwright test e2e/landing.spec.ts e2e/about.spec.ts --project=chromium. Note every rule ID in the violations array of the two axe scans (e.g., color-contrast, button-name, link-name, aria-allowed-attr, focus-visible).

    Step 2: For each violation, apply the smallest fix that resolves it:
    - color-contrast violations: increase text-color contrast against background by swapping the offending color to a design-token hex with sufficient contrast (typically --text-primary e2e8f0 against --bg-deep 0b1117 is 14:1 — safe; --text-muted 8b96a8 against the same bg is approx 5:1 — borderline; if axe flags it on a non-essential label, leave it; if it flags it on a content row, swap to --text-primary).
    - button-name / link-name violations: add aria-label attributes to the offending buttons or links (e.g., the activityBar buttons in Sidebar.tsx lines 81-134 already have aria-label values; verify none was missed by axe).
    - aria-allowed-attr / role violations: the file rows in Sidebar.tsx (lines 60-73) use role button with tabIndex 0 and onKeyDown — confirm axe is happy; if not, switch to a true button element wrapped around the row.
    - heading-order / landmark violations: usually surface in MDX content (about page) — fix in resume.mdx if needed (note: resume.mdx is not in files_modified above; if axe surfaces a heading violation, add the file to the plan summary as a discovered scope add).

    Step 3: Add visible focus indicators. For every interactive element class that does not already have a :focus-visible rule with a clear outline, add one to the appropriate CSS Module. Required pattern:
    - In the relevant .module.css file, add a rule for the existing class like the file row in Sidebar.module.css: under the existing .treeRow selector, add an &:focus-visible block (CSS nesting is supported by the build via tailwindcss postcss processing — if nesting fails, write a separate top-level selector).
    - Rule body: outline 2px solid hex 79b8ff (--blue), outline-offset 2px, border-radius optional (match parent).
    - Apply to: .treeRow (sidebar file rows), .treeFolder (sidebar folder headers), .actBtn (activity bar buttons in Sidebar.tsx), .runBtn (TopBar Run button — use --green hex 3ddc84 for visual hierarchy), .tabBtn (Terminal tab buttons), .statusItem (StatusBar interactive items), .downloadBtn (about page PDF link in about.module.css), and any other element with an onClick or role=button that lacks an existing focus state.

    Step 4: Re-run axe scan via pnpm exec playwright test e2e/landing.spec.ts e2e/about.spec.ts --project=chromium. Confirm violations array is empty for both pages. If any violations remain, iterate.

    Per D-15 in CONTEXT.md: focus indicators verified by axe-core scan plus any remaining fixes applied inline. No manual audit required beyond what axe reports — but task 2 below adds a manual keyboard tab-through as belt-and-suspenders for the T-03-03 disposition (axe catches only ~30-40% of WCAG issues per security_requirements).

    Do NOT add new components. Do NOT switch UI libraries. Do NOT introduce a new icon set. The fixes are surgical CSS additions and (rarely) aria-label additions to existing TSX.

    Do NOT use outline none anywhere — that creates an a11y regression. If a design requirement insists on no outline, replace with box-shadow ring of equivalent contrast.

    Do NOT touch files outside the IDE component directory + about module unless axe forces it (e.g., a violation in resume.mdx). Document any scope add in the plan SUMMARY.
  </action>
