# Plan 06-01: Vitest Infrastructure Setup

## Objective

Install Vitest and its peer dependencies, configure it for React + jsdom, add the `pnpm test` script, and wire the test run into CI so all future unit tests execute on every push.

No test files are written in this plan — that work is in 06-02 and 06-03. This plan only creates the tooling foundation.

## Tasks

### Task 1 — Install Vitest and testing dependencies

<read_first>
- package.json (current devDependencies and scripts)
- tsconfig.json (path aliases — @/* maps to ./src/*)
</read_first>

<action>
Run the following pnpm add command to install all required devDependencies:

```
pnpm add -D vitest @vitejs/plugin-react @testing-library/react @testing-library/user-event @testing-library/jest-dom jsdom
```

- `vitest` — test runner (replaces Jest; Vite-native, TypeScript-native)
- `@vitejs/plugin-react` — JSX transform plugin required by vitest for React components
- `@testing-library/react` — render() + screen + fireEvent for component tests
- `@testing-library/user-event` — realistic user interaction simulation (click, type)
- `@testing-library/jest-dom` — extends expect with .toBeInTheDocument(), .toHaveTextContent(), etc.
- `jsdom` — browser-like DOM environment for Vitest (required for React component rendering)
</action>

<acceptance_criteria>
- `pnpm list vitest @vitejs/plugin-react @testing-library/react @testing-library/user-event @testing-library/jest-dom jsdom` exits 0 and lists all six packages
- All six packages appear in package.json devDependencies after the install
- pnpm-lock.yaml is updated (no manual lock editing needed)
</acceptance_criteria>

### Task 2 — Create vitest.config.ts

<read_first>
- tsconfig.json (paths: "@/*" → "./src/*" — must be mirrored in vitest resolve.alias)
- package.json (confirm vitest is now installed)
</read_first>

<action>
Create `vitest.config.ts` at the project root (next to package.json). The file must:

1. Import `defineConfig` from `vitest/config` (not `vite/config` — different entry point)
2. Import `react` from `@vitejs/plugin-react`
3. Import `path` from `node:path`
4. Export `defineConfig({ plugins: [react()], test: { ... }, resolve: { alias: { '@': path.resolve(__dirname, './src') } } })`

The `test` block must include:
- `environment: 'jsdom'` — enables DOM APIs (document, window, etc.) in tests
- `globals: true` — makes describe/it/expect available without imports (matches Jest muscle memory)
- `setupFiles: ['./src/test/setup.ts']` — runs the jest-dom setup before each test file
- `include: ['src/**/*.{test,spec}.{ts,tsx}']` — scopes test discovery to src/

The `resolve.alias` block must mirror tsconfig paths exactly: `'@'` → `path.resolve(__dirname, './src')`.

Do NOT set `css: false` — Vitest's default CSS module handling (returns empty objects) is correct for behavioral tests; real class names are not needed.
</action>

<acceptance_criteria>
- `vitest.config.ts` exists at project root
- File contains `environment: 'jsdom'`
- File contains `globals: true`
- File contains `setupFiles: ['./src/test/setup.ts']`
- File contains `'@': path.resolve(__dirname, './src')`
- `pnpm exec vitest --version` exits 0 (vitest CLI is reachable)
</acceptance_criteria>

### Task 3 — Create src/test/setup.ts

<read_first>
- vitest.config.ts (confirm setupFiles points to ./src/test/setup.ts)
</read_first>

<action>
Create `src/test/setup.ts` with a single import:


This file runs before every test file (via `setupFiles` in vitest.config.ts). The import extends Vitest's `expect` with jest-dom matchers: `.toBeInTheDocument()`, `.toHaveTextContent()`, `.toHaveAttribute()`, `.toBeVisible()`, etc.

Create the `src/test/` directory if it does not exist.

### Task 4 — Add test scripts to package.json

<read_first>
- package.json (current scripts block — must not break existing dev/build/lint/typecheck/ci-check)
</read_first>

<action>
Add two entries to the `scripts` block in package.json:

1. `"test": "vitest run"` — runs all tests once (CI mode: exits with code 0/1 based on pass/fail)
2. `"test:watch": "vitest"` — interactive watch mode for local development

The existing scripts (dev, build, start, lint, typecheck, ci-check) must not be modified.

Also update the existing `"ci-check"` script to include test:
- Current: `"ci-check": "pnpm lint && pnpm typecheck && pnpm build"`
- Updated: `"ci-check": "pnpm lint && pnpm typecheck && pnpm test && pnpm build"`

The `pnpm test` call goes between typecheck and build so type errors surface before test failures.
</action>

<acceptance_criteria>
- `package.json` scripts contains `"test": "vitest run"`
- `package.json` scripts contains `"test:watch": "vitest"`
- `ci-check` script includes `pnpm test` between typecheck and build
- `pnpm run test --help` exits 0 (script is recognized by pnpm)
</acceptance_criteria>

### Task 5 — Add pnpm test step to CI workflow

<read_first>
- .github/workflows/ci.yml (current quality-gate job steps — must insert test step at the right position)
</read_first>

<action>
Edit `.github/workflows/ci.yml`. In the `quality-gate` job, add a new step named "Unit tests" that runs `pnpm test`. Insert it after the "Typecheck" step and before the "Build" step:

```yaml
      - name: Unit tests
        run: pnpm test
```

This ensures unit tests run after type checking (so type errors surface first) but before the full Next.js build (fast feedback loop — tests fail before spending 60s on a build).

Do not modify any other jobs or steps.
</action>

<acceptance_criteria>
- `.github/workflows/ci.yml` contains a step with `name: Unit tests` and `run: pnpm test`
- The Unit tests step appears after the Typecheck step and before the Build step in the quality-gate job
- The playwright-tests job is unchanged
- YAML is valid (no syntax errors that would fail `actions/runner` parsing)
</acceptance_criteria>
