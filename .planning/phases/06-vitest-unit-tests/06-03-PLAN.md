# Plan 06-03: File-Data and Sidebar Tests

## Objective

Write Vitest tests for (a) `src/lib/files-data.ts` to validate the shape of every file entry and log entry (TEST-02), and (b) `src/components/ide/Sidebar.tsx` to verify that file entries render as interactive buttons and that click events trigger the correct callbacks (TEST-03).

Both test files can be written in parallel as they target different modules with no shared state.

## Background

**files-data.ts** exports `FILES` (a `Record<string, FileEntry>`) and `SAMPLE_LOGS` (a `LogEntry[]`). These are pure data — no DOM needed. Tests run in the default Vitest `jsdom` environment but could equally run in `node`.

**Sidebar.tsx** is a `"use client"` React component. It renders an `<aside>` with role-based buttons for file entries. CSS modules (Sidebar.module.css) import to empty objects in Vitest by default, so class name assertions are avoided — behavioral assertions only (roles, text content, event callbacks).

Key behavioral facts:
- `ROOT_FILES` (`README.md`, `contact.json`) render as role="button" elements at the bottom of the tree, always visible when sidebar is open.
- `ABOUT_FILES` (`bio.json`, `experience.yaml`, `skills.yaml`) are inside the `about/` folder which is **collapsed by default** (`open.about = false`).
- `TEST_FILES` are inside the `tests/` folder which is **collapsed by default** (`open.tests = false`).
- Clicking a folder header div (role="button", aria-label="Toggle about folder") expands the folder.
- Clicking a file row (role="button", text=filename) calls `setActiveFile(name)`, `openTab(name)`, and optionally `onSelect()`.
