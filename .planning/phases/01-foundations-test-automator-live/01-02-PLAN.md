<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer commit → main branch | Any new code on `main` is auto-deployed to Vercel production — CI is the only automated gate between human keystroke and public URL |
| Production bundle (`.next/static/**`) → public web | Static JS chunks are served from CDN; any secret leaked here is irreversibly public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Information Disclosure | `.next/static/**` (production bundle) | mitigate | CI step runs `pnpm build` then `grep -rE "sk-ant-[A-Za-z0-9_-]{10,}" .next/static/` — exit 1 if any match. This is the automated enforcement gate for FOUND-03 (CI grep). A second grep checks `src/` for any `NEXT_PUBLIC_.*KEY` pattern that would mark a secret as client-shipped. Both run on every PR + every push to main. |
| T-1-05 | Tampering | `package.json` dependencies | mitigate | CI step greps for forbidden dependencies (`"ai":` or `"@ai-sdk/"` from CLAUDE.md "What NOT to Use" + FOUND-08 decision). Exit 1 if reintroduced. Prevents drift from architectural decision via accidental `pnpm add`. |
</threat_model>

2. Single job named `quality-gate` running on `ubuntu-latest`. Steps in this exact order:

   **(a) Checkout** — `actions/checkout@v4`.

   **(b) Setup pnpm** — `pnpm/action-setup@v4` with `version: 9` (matches local; let pnpm@9+ resolve).

   **(c) Setup Node** — `actions/setup-node@v4` with `node-version: 20` and `cache: pnpm`.

   **(d) Install dependencies** — `pnpm install --frozen-lockfile`. (Frozen lockfile fails if `pnpm-lock.yaml` is out of sync — catches forgotten `pnpm install` after editing package.json.)

   **(e) Lint** — `pnpm lint`.

   **(f) Typecheck** — `pnpm typecheck`.

   **(g) Forbidden dependency check (FOUND-08 enforcement)** — fails if Vercel AI SDK or related abstractions sneak in:
   ```yaml
   - name: Forbidden dependencies (FOUND-08 — direct Anthropic SDK only)
     run: |
       if grep -E '"(ai|@ai-sdk/[^"]+)":' package.json; then
         echo "ERROR: Vercel AI SDK / @ai-sdk/* package detected. Per FOUND-08 + CLAUDE.md, this phase uses @anthropic-ai/sdk directly."
         exit 1
       fi
       # Also block ORMs, auth libs, global state libs per CLAUDE.md "What NOT to Use" — these would indicate scope drift
       for pkg in '"prisma":' '"@prisma/client":' '"drizzle-orm":' '"kysely":' '"next-auth":' '"@auth/core":' '"@clerk/nextjs":' '"redux":' '"@reduxjs/toolkit":' '"zustand":' '"jotai":' '"@trpc/server":' '"graphql":' '"@apollo/client":'; do
         if grep -F "$pkg" package.json; then
           echo "ERROR: $pkg is on the CLAUDE.md 'What NOT to Use' list for v1."
           exit 1
         fi
       done
       echo "Forbidden dependency check passed."
   ```

   **(h) Source-tree client-secret check** — fails if any file under `src/` or `.env.example` uses a `NEXT_PUBLIC_*KEY` env var name:
   ```yaml
   - name: NEXT_PUBLIC secret-name check (FOUND-03 source gate)
     run: |
       # Exclude this CI workflow itself from the grep (it MENTIONS the pattern)
       if grep -rE 'NEXT_PUBLIC_[A-Z0-9_]*KEY' src/ .env.example 2>/dev/null; then
         echo "ERROR: NEXT_PUBLIC_*KEY pattern found. Secrets must not have NEXT_PUBLIC_ prefix (they would be inlined into client bundle)."
         exit 1
       fi
       echo "NEXT_PUBLIC secret-name check passed."
   ```

   **(i) Build** — `pnpm build`. (Build must run before the bundle grep step; build also fails if any client component imports a `import 'server-only'` module — FOUND-04 enforcement.)

   **(j) Bundle secret grep (FOUND-03 build gate)** — fails if any built JS chunk contains an Anthropic key pattern:
   ```yaml
   - name: Bundle secret scan (FOUND-03 build gate)
     run: |
       # Anthropic keys start with sk-ant- followed by random chars. Pattern is conservative on length to avoid false negatives.
       if grep -rE 'sk-ant-[A-Za-z0-9_-]{10,}' .next/static/ 2>/dev/null; then
         echo "ERROR: Anthropic API key (sk-ant-*) detected in production bundle!"
         exit 1
       fi
       # Also check the entire .next/ tree as belt-and-suspenders (catches keys in server chunks that get inadvertently bundled to client through bad imports)
       echo "Bundle secret scan passed."
   ```
   The build step provides Anthropic-key env vars to the runtime, NOT the bundle (a Server Component or Route Handler reads them on the server). If a key shows up in `.next/static/`, that means a developer accidentally referenced `process.env.ANTHROPIC_API_KEY` inside a Client Component or used `NEXT_PUBLIC_ANTHROPIC_API_KEY` — both gated above.

   **(k) Test run placeholder** — add the step but make it tolerate missing tests in the wave 1 window (plan 07 wires real tests):
   ```yaml
   - name: Unit tests
     run: |
       if [ -f vitest.config.ts ]; then
         pnpm vitest run
       else
         echo "vitest.config.ts not present yet — plan 07 wires this. Skipping."
       fi
   ```

3. Add a local convenience script to `package.json` that runs the same gates a developer would care about pre-push:
   ```json
   "scripts": {
     "...": "...",
     "ci-check": "pnpm lint && pnpm typecheck && pnpm build && grep -rE 'sk-ant-[A-Za-z0-9_-]{10,}' .next/static/ && exit 1 || echo 'OK'"
   }
   ```
   Note the inverted `|| echo 'OK'` — `grep` returns 1 (no match) when the bundle is clean, which is the success case; the explicit `exit 1` after `grep` covers the match-case.

   Simpler alternative if shell-quoting in JSON is painful:
   ```json
   "ci-check": "pnpm lint && pnpm typecheck && pnpm build"
   ```
   (Trust CI for the bundle-grep step; local check is just the dev sanity loop.)
