# Milestone v1.0: MVP — SDET Portfolio Site

**Status:** ✅ SHIPPED 2026-05-23
**Phases:** 1-3
**Total Plans:** 14

## Overview

A dark IDE-style portfolio site for a senior SDET / QA automation engineer. The site itself is the demo — built with care, tested with real TypeScript Playwright E2E tests displayed in the IDE chrome's file explorer. No AI APIs, no backend services: just craft on a static/SSR foundation. Every phase boundary is a URL that can be dropped on a resume.

## Milestone Summary

### Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Pivot from "AI toolkit" to "IDE-style portfolio with Playwright showcase" (2026-05-18) | Tools requiring API keys delay ship; IDE portfolio proves craft immediately with zero backend | ✓ Correct — shipped in 9 days |
| Hand-rolled TypeScript tokenizer (not Shiki runtime) | files-data.ts is client-bundled; no server-side highlighter needed for static content | ✓ Clean — XSS-safe ReactNode[] output |
| Embed spec file content as inline string literals | files-data.ts is client-bundled, can't use fs.readFileSync | ✓ Works — minor content drift vs. actual e2e/ files |
| Two-variant Footer (compact for landing, full for /about) | Different contexts need different information density | ⚠️ Introduced double-footer bug on /about (fixed in q02) |
| GitHub Actions workflow_dispatch for Run Smoke Test | Real CI trigger proves the feature is wired to production | ✓ Correct — learned that 204 No Content requires a follow-up GET /runs to find run ID |
| No AI APIs in v1 | Eliminates API key ops, rate limiting, cost concerns; ships in days | ✓ Correct for v1 timeline |
